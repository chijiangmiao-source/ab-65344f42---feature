# 带符号标记排列 · 规范倒位审计页

基因组装配复核场景的纯浏览器工具：输入 3 至 7 个带符号标记组成的排列
（绝对值必须恰好为 1 至 n 且互异），在**线性 / 环状两种拓扑**下于浏览器内
**精确枚举全部最短倒位方案**，给出：

- 到全正顺序（环状为正向环序）的**最少倒位步数**；
- **最短方案总数**（bigint 任意精度，十进制展示）；
- **规范方案**：在全部最短方案中，按每步操作对序列的字典序选出的唯一方案，
  可逐步 / 拖动滑块查看每一步的状态；
- **深度 × 操作矩阵**：每格表示“在该深度选择该操作”的最短方案数量，并标注
  - 绿：**全部**最短方案都出现；
  - 黄：**部分**最短方案出现；
  - 灰：**任何**最短方案中均未出现；

  线性模式下列为闭区间 `[i,j]`；环状模式下列为切口对 `(a,b)`。点击任意格，
  轨迹视图联动跳转到对应深度并高亮该步区间 / 实际弧段（规范选择始终白色描边）。
- 非法输入一次性合并给出全部错误，输入文本始终保留。

**无业务后端、无持久化、无任何在线调用。** 容器只运行一个极简静态文件服务器
（`server/server.mjs`，约 100 行），计算全部在浏览器（Web Worker）内完成。

## 拓扑切换

输入区提供**线性 / 环状**分段切换；切换后立即清空上一模式的审计结果、矩阵选中
与浏览深度，必须在新拓扑下重新审计（两种模式的结果互不复用）。

### 线性（语义与旧版完全一致）

选择闭区间 `[i, j]`（1 基），将区间内标记次序反转，并同时翻转每个符号。
位置 1 与 n 不相邻。例：`[1,-3,-2,4]` 在 `[2,3]` 上倒位 → `[1,2,3,4]`，
故最短步数为 **1**。输入、距离、方案计数与矩阵语义均保持不变。

### 环状

环上**没有固定首标记，也没有固定的观察链方向**，因此同一物理排列的

- 任意循环旋转（n 种），以及
- 整体反向并翻号（negate+reverse，再 ×n 种旋转）

共 2n 个表示视为**同一状态**；每个状态取等价类中压缩码最小的表示作为规范表示。

- **切口与弧**：切口 k 位于位置 k 与 k+1 之间，切口 n 位于位置 n 与 1 之间
  （n 后接 1）。一次倒位由**两个不同切口**确定其间的一段弧；倒位整环
  （不下第二刀）无效，故一共只有 `n(n-1)/2` 个切口对。
- **互补弧等价**：两个切口把环切成两段，倒位任一段得到的后继状态等价
  （另一段的结果等于本段结果整体反向翻号后再旋转），故一对切口只产生一条边。
- **去重与命名**：同一状态对之间由互补弧或不同表示产生的重复边只计一次，
  并以**当前规范表示**下字典序最小的切口对 `(a,b)`（a<b）命名。这同时修复了
  线性坐标把跨首尾倒位误判为“不可选”的问题。
- 审计仍精确给出到**正向环序**的最少步数、任意精度方案总数与规范轨迹；
  轨迹以环形 SVG 展示，逐步浏览时按**标记绝对值**跟踪弧段，重新规范化不会
  跳错标记；点击矩阵格即在环上高亮实际弧段（含切口编号）。

## 本地开发（Node 20+）

```bash
npm ci
npm test          # vitest：含对 n=3 全部 48 个排列的暴力枚举交叉验证
npm run build     # tsc --noEmit + vite 静态构建到 dist/
npm run dev       # 本地热更新开发
PORT=8080 npm run serve:static   # 用静态服务器发布已构建的 dist/
npm run smoke     # 对运行中的服务做 HTTP 冒烟（BASE_URL 可覆盖）
```

```bash
docker compose up -d --build web
# 浏览器打开 http://localhost:8080
```

宿主机端口可配置：

```bash
WEB_PORT=9090 docker compose up -d web       # 宿主机 9090 -> 容器 8080
```

## 一次性验证服务 verify

```bash
docker compose run --build verify
```

`verify` 服务会在 `web` 健康检查通过后自动执行，并以**容器退出码**报告结果
（`docker compose ps -a verify` 可查看 `Exited (0)`）：

1. 单元测试（vitest，含独立暴力枚举交叉验证距离 / 总数 / 规范字典序）；
2. 构建检查（TypeScript 类型检查 + Vite 生产构建）；
3. 需求核查：`[1,-3,-2,4]` 线性最短步数为 1（唯一倒位 `[2,3]`）、
   重复绝对值被拒绝；环状模式下旋转 / 反向翻号等价、跨首尾倒位可达、
   整环操作无效、重复边只计一次并按字典序最小切口对命名；
4. HTTP 冒烟：等待页面可访问后检查 `/healthz`、首页 HTML 与构建资源。

## 算法说明

线性状态空间至多 `2^n · n!`（n=7 时 645,120 个状态；环状再对至多 2n 个
旋转 / 反向表示取商）。状态压进一个整数（每个带符号标记 4 位），倒位用
位运算枚举；环状规范化用位运算做循环移位与整体反向翻号，在 2n 个表示中
取最小压缩码：

1. 前向 BFS（初始态出发）得到最短距离；邻居按操作对字典序枚举
   （线性 `(i,j)`，环状去重后的切口对 `(a,b)`），首次到达各状态的父边即
   构成字典序最小的最短方案；
2. 反向 BFS（目标态出发，只保留位于某条最短路径上的状态），分层 DP 计算
   每个状态到目标的最短路径数（bigint）；
3. 从初始态逐层枚举“最短边”，按操作聚合格计数
   （边计数 = 前缀方案数 × 后缀方案数），得到深度×操作矩阵。环状模式中
   同一状态对的重复边（互补弧、不同表示）在邻居枚举处即已合并，只按字典序
   最小的切口对计一次。

因此结果不是贪心近似——“眼前减少断点最多”的局部贪心可能错过全局最短修复、
也无法暴露等长替代路径；这里枚举的是全部最短方案。
