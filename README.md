# 带符号标记排列 · 规范倒位审计页

基因组装配复核场景的纯浏览器工具：输入 3 至 7 个带符号标记组成的排列
（绝对值必须恰好为 1 至 n 且互异），在浏览器内**精确枚举全部最短倒位方案**。
输入区可在两种拓扑间切换：

- **线性拓扑**：固定首标记与观察方向，倒位为闭区间 `[i,j]`；
- **环状拓扑**：不设固定首标记/观察链方向，循环旋转与整体反向并翻号视为
  同一状态。切口 `k` 位于位置 `k` 与 `k+1` 之间（`n` 后接 `1`），两个不同
  切口确定一段弧；整环操作（两切口重合）无效，互补弧不另计。

两种模式都给出：

- 到全正顺序（环状为正向环序）的**最少倒位步数**；
- **最短方案总数**（bigint 任意精度，十进制展示）；
- **规范方案**：在全部最短方案中，按每步操作 `(起, 止)` / `(切口 a, 切口 b)`
  序列的字典序选出的唯一方案，可逐步 / 拖动滑块查看每一步的状态；
- **深度 × 操作矩阵**：每格表示“在该深度选择该操作”的最短方案数量，并标注
  - 绿：**全部**最短方案都出现；
  - 黄：**部分**最短方案出现；
  - 灰：**任何**最短方案中均未出现；

  点击任意格，轨迹联动跳转到对应深度。线性模式高亮该步区间；环状模式在
  环形轨迹上高亮该切口对夹定的**实际弧段**（若该切口名来自此深度另一个
  等价规范表示，则展示其见证态）。规范选择始终白色描边。
- 非法输入一次性合并给出全部错误，输入文本始终保留。

切换拓扑会丢弃上一模式的审计结果与选中深度并要求重新审计，两种模式的
输入文本、线性距离/方案计数/矩阵语义互不影响。

**无业务后端、无持久化、无任何在线调用。** 容器只运行一个极简静态文件服务器
（`server/server.mjs`，约 100 行），计算全部在浏览器（Web Worker）内完成。

## 倒位语义

- 线性：选择闭区间 `[i, j]`（1 基），将区间内标记次序反转并翻转每个符号。
  例：`[1,-3,-2,4]` 在 `[2,3]` 上倒位 → `[1,2,3,4]`，故最短步数为 **1**。
- 环状：每个状态取全部 `2n` 个线性表示（n 个旋转 × 2 个朝向）中带符号序列
  字典序最小者为**规范表示**。在规范表示上对位置 `a+1..b`（即切口对 `(a,b)`
  夹住的正向弧）倒位后重新规范化。互补弧、不同表示导致的重复边只计一次，
  边以“当前规范表示下字典序最小的切口对”命名；整环（`a=b`）不是合法操作，
  因此每态只有 `C(n,2)` 个操作（如 `[3,-2,-1]` 环上一步即可到正向环序，
  线性下则需要更多步——跨首尾倒位在环状模式中可选）。

## 本地开发（Node 20+）

```bash
npm ci
npm test          # vitest：线性 n=3 全量暴力交叉验证 + 环状商空间交叉验证与显示链不变量
npm run build     # tsc --noEmit + vite 静态构建到 dist/
npm run dev       # 本地热更新开发
PORT=8080 npm run serve:static   # 用静态服务器发布已构建的 dist/
npm run smoke     # 对运行中的服务做 HTTP 冒烟（BASE_URL 可覆盖）
```

## Docker 发布

```bash
docker compose up -d --build web
# 浏览器打开 http://localhost:8080
```

宿主机端口可配置：

```bash
WEB_PORT=9090 docker compose up -d web       # 宿主机 9090 -> 容器 8080
# 或写入 .env（参见 .env.example）
```

健康检查：`GET /healthz` 返回 `200 {"status":"ok"}`；
Dockerfile 与 Compose 均声明了基于该端点的容器健康检查。

## 一次性验证服务 verify

```bash
docker compose run --build verify
```

`verify` 服务会在 `web` 健康检查通过后自动执行，并以**容器退出码**报告结果
（`docker compose ps -a verify` 可查看 `Exited (0)`）：

1. 单元测试（vitest，含独立暴力枚举交叉验证距离 / 总数 / 规范字典序）；
2. 构建检查（TypeScript 类型检查 + Vite 生产构建）；
3. 需求核查：`[1,-3,-2,4]` 最短步数为 1（唯一倒位 `[2,3]`）、
   重复绝对值被拒绝；
4. HTTP 冒烟：等待页面可访问后检查 `/healthz`、首页 HTML 与构建资源。

## 算法说明

状态压进一个整数（每个带符号标记 4 位），倒位用位运算枚举，结果精确：

- 线性状态空间至多 `2^n · n!`（n=7 时 645,120 个状态），每态至多
  `n(n+1)/2 = 28` 个倒位；
- 环状在商空间（旋转 `C_n` 与整体反向翻号自由作用）上运算，状态数至多
  `2^(n-1)·(n-1)!`（n=7 时 23,040），每态至多 `C(n,2) = 21` 个切口对。

两种拓扑共用同一审计骨架：

1. 前向 BFS（初始态出发）得到最短距离；邻居按操作字典序枚举（环状枚举在
   规范化后对同一后继去重并保留最小切口对名），首次到达各状态的父边即构成
   字典序最小的最短方案；
2. 反向 BFS（目标态出发，只保留位于某条最短路径上的状态），分层 DP 计算每个
   状态到目标的最短路径数（bigint）；
3. 从初始态逐层枚举“最短边”，按操作聚合格计数
   （边计数 = 前缀方案数 × 后缀方案数），得到深度×操作矩阵。

因此结果不是贪心近似——“眼前减少断点最多”的局部贪心可能错过全局最短修复、
也无法暴露等长替代路径；这里枚举的是全部最短方案。环状模式另有 n=3 全量、
n=4 全量与 n=5 全量（3,840 个输入）对独立商空间暴力模型的交叉验证
（距离、任意精度方案数、字典序规范轨迹、矩阵行和与见证态）。
